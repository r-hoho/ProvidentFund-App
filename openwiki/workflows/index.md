# Files

- [Beneficiary Flow](beneficiary-flow.md) - The beneficiary manager's four frontend views (current / edit / history / sign), the {name, rel, pct, address} JSON model with title-prefix merge/split, max-5 + sum=100 validation, the Same-as-Above address copy, signature capture, and processUpdateBeneficiaries — the append-only ledger write, audit row, immediate-effective best-effort letter/email, and letter-failure admin alert.
- [Confirmation Pipeline — Email, Letters & Analytics](confirmation-pipeline.md) - The cross-cutting post-commit side-effect discipline every action handler runs after its sheet writes succeed — best-effort generateLetter, sendActionConfirmation, patchAuditEventData, and trackFeatureAction, none of which may throw or roll back the action, plus the GA4 server-side Measurement Protocol and the letter-failure admin alert.
- [Enrollment Flow](enrollment-flow.md) - The 5-step enrollment wizard (client) and processEnrollment (server) — resolving the user by Work_Email, generating the EN- transaction id, upserting the Enrollments row (first enroll vs re-enroll; First_Enrolled_Date only when blank, Current_Enrolled_Date always today), appending the Beneficiaries ledger, then the best-effort post-commit side-effects (generateLetter ENROLLMENT, sendActionConfirmation, patchAuditEventData, trackFeatureAction) and how the step-5 signature data URL threads through to the PDF and the signedAt audit stamp.
- [Plan Change, Withdrawal & Cancel](plan-change-withdraw-cancel.md) - The three "other" write-path actions beyond enrollment — processChangePlan (the 6-month plan-change lock measured from max(Current_Enrolled_Date, Last_Plan_Change_Date) and the upsert of Current_Plan + Last_Plan_Change_Date), processWithdrawal (clearing the plans, ticking Withdrawal_Count, stamping Last_Withdrawal_Date), and cancelTransaction (reverting Enrollments fields from the SUBMITTED row's priorValues inside the editable window and appending a CANCELLED audit row with the same Transaction_ID) — plus the in-progress pending-transaction box that derives cancellable rows from Audit_Log and ties all three together.
- [Profile Read & Eligibility Path](profile-and-eligibility.md) - The main read path — getUserProfile() resolves the signed-in user by email from the Users sheet, joins the Enrollments row (current plan, investment plan, withdrawal count, dates), reads the Beneficiaries ledger bottom-up (current row plus history), calls getPendingTransactions for the in-progress box, and computes eligibility (probation, cooldown, tenure, match tier); plus checkPlanChangeEligibility() and how populateUI renders the dashboard and the cooldown/withdrawal messages the whole UI hangs off.
